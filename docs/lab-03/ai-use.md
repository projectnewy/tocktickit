## Reflection

The pattern that paid off most this sprint was treating every non-trivial claim as something to verify, not assert: running the exact test/typecheck commands before writing a status line, walking the real login→role→screen flow in a browser instead of trusting the component diff, and — most usefully — catching my own about-to-be-written false claim in `tests.md` by grepping for the test I was about to cite before citing it. That last one is a direct echo of Lab 2's own reflection note about the AI-use log itself needing the same discipline as the code; this time the discipline caught a real gap (two planned unit tests that had quietly never been written) instead of just a log-hygiene issue.

The two peer-review cycles (PR #42, #43) were the most concrete evidence all sprint that "the AI wrote it and the tests passed" is not the same as "it's done": both PRs had complete test coverage and passed CI, and both still had real, specific, user-facing gaps — an incomplete UI control, a fail-open authorization check, a contrast violation, missing success feedback, an avoidable error round-trip — that only surfaced from a second pair of eyes reading the actual rendered behavior against the spec's exact wording (ui-spec.md §4's "Reassign dropdown," §8.6's success-state requirement). Every one of those was fixed and re-verified in a live browser, not just patched to satisfy the review comment's literal text.

Non-obvious environment gotchas repeated from Lab 2, confirming they're real properties of this setup rather than one-off flukes: `prisma migrate dev` still refuses to run in this non-interactive shell (hand-written migration SQL is the reliable path), and Docker Desktop still takes 15–20+ minutes to become responsive after launch on this machine even once its processes show as running. Both are now assumed defaults rather than surprises to re-diagnose each time.
