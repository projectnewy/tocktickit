## Reflection

Early prompts worked best when the assistant read the actual Lab 1 code and the full labsheet before proposing any design, rather than guessing at conventions — this caught real constraints (the `.js`-extension ESM import style, the `getPrisma()` lazy singleton, `rootDir`/`include` boundaries) that would have caused avoidable rework if assumed instead. Writing `specification.md`, `tests.md`, `ui-spec.md`, and `api-spec.md` before any implementation branch, with reasoning for each non-obvious decision (why a header instead of a cookie, why 404 instead of 403, why a counter table instead of `MAX()+1`), made every later branch faster to build and review because the hard calls were already made and justified once.

The test suite caught two real, non-obvious bugs neither of us would have thought to check for in advance: mounting `requesterContext` as bare router-level middleware silently made it fire on an unrelated 404 route (401 instead of 404) — caught immediately by a test written for that exact case; and a Windows/MSYS `curl` quirk with `/tmp` paths during manual verification, which looked exactly like a server-side upload bug until isolated by testing with a different file path. Both were found by actually running things — the automated suite for the first, a live `curl` walkthrough for the second — not by inspection.
